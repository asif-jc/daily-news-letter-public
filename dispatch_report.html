Architecture decision

Keep the retained evidence-first workflow and remove the abandoned executable alternatives. One installed news package now owns ingestion, article analysis, event grouping, editorial selection, synthesis, persistence, rendering and publication. Its source registry includes RNZ Politics and Business. Original reader styling and database records are preserved. Old executable workflow resumes are explicitly unsupported; their stored editions and evidence remain intact.

Generation runs with private model/database settings. Export creates only reader HTML, the banner, published archive pages and a release hash manifest. GitHub deploys that subset. Confirmation compares the intended saved edition, local candidate and delivered files before recording publication. Build/export alone never imply delivery.

Standards review: Astra

Astra reviewed the whole application, including the legacy packages and publication workflows. The principal findings were duplicated execution paths, source ownership in the MVP package, mixed responsibilities, misleading maintained documentation and obsolete dependencies. These were resolved by consolidating the active path, moving responsibilities into named modules, deleting the dead agent/MVP packages and making pyproject.toml the one dependency manifest. Old generated files were copied into ignored local storage before retirement from the maintained tree.

Additional correctness findings were fixed: malformed multi-source outputs now receive bounded repair, unusable empty editions fail, downloaded bytes are bounded, source URLs use the public publisher policy, tests require explicit loopback settings and clean their own schemas, and CI covers the canonical package and main branch. A final Astra review found the deployment-only manifest validator was weaker than local export; both now invoke the shared artifact allowlist, exact inventory, hash and symlink checks. Astra's follow-up found no remaining Important/Critical issue in the reviewed code scope. Content quality and actual delivery remain separate checks.

Spec review: independent

The independent Spec review identified missing NZ feeds/extraction, the unchanged legacy deployment path, incomplete canonical cleanup and seven-day browsing truncated by edition count. RNZ feeds and extraction support are configured, the deployment workflow now publishes exported reader files, prototypes are retired, and calendar-window archive tests cover more than seven editions. Live selected NZ stories and final delivery are still pending.

Executed evidence so far

  • 109 tests passed without skips against the owned local PostgreSQL instance.
  • Astra independently ran 65 service-free core tests, then 16 publication/CLI checks.
  • Official RNZ Politics and Business feeds returned HTTP200 and 17/16 entries. One article from each was retrieved as article text.
  • The built wheel contains the canonical CLI, reader assets, profile and migrations, with no prototype packages.
  • The public-file credential scan found zero credentials. A synthetic network fixture was changed to loopback; retired author-contact details were removed from the reader footer. The old banner also contained GPS metadata; the active asset was stripped of location/device metadata without re-encoding its pixel stream. The pre-existing public history was not rewritten. Detailed scan output remains ignored.

Known limits and accepted debt

Model self-review is not independent factual verification. Lexical proposals can miss paraphrases; update judgments can mistake added context for new developments. Six feeds do not provide exhaustive coverage. Read state remains browser-local. No recurring generation scheduler or automatic retention deletion is installed. Existing PostgreSQL records are retained; the schema is not rewritten to match the package rename.
