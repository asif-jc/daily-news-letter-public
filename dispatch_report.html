Tasks and architecture

PR #25 was independently reviewed again and merged as d512beb. It contains the warm story reader, Daily News branding, prominent edition date and styled sidebar controls. The follow-up release changes the GitHub name to daily-news, updates maintained entry points, exports that reader to the production artifact, and replaces the old video with a new story-style film and a usable player.

The reader stays Python-generated static HTML with its existing safe-field and source-URL boundary. The tour is a small static HTML page with native video controls, chapter jumps, captions, a transcript, download and a separate live-reader action. No frontend framework, subscriber backend, extra news feed or agent platform was added.

The Pages workflow first verifies the strict reader-only site/ export, then copies it and exactly four files from docs/tour/ to its deployment directory. The MP4, poster, captions and player have one canonical source directory. Raw captures, authoring projects, private settings and diagnostics stay ignored.

The playback bug

The old README pointed to a GitHub raw MP4 response with application/octet-stream. Its H.264/AAC encoding was compatible, but this was a download route rather than a dependable interactive player. The new entry point is an HTML page with a relative video/mp4 source. Native playback, seeking and chapter controls are verified separately from merely producing a file.

Local testing also exposed a server dependency: a basic Python file server reset a seek to the beginning. A range-aware server returned 206 Partial Content, Content-Type: video/mp4 and the expected byte range. Real browser chapter actions then reached 8.06s and 14.12s, played without media error, and paused with the native keyboard control. Production MIME/range/playback checks are release gates, not inferred from local tests.

Preserve publication provenance

The first publication receipt is immutable. It cannot be replaced just because HTML, artwork or a repository URL changes. The new confirm-presentation command shares the same retained-edition and delivered-file verification as first publication, then records an immutable receipt in the existing stages table. Its key includes manifest digest and normalized URL; its output links to the original publication digest.

The edition payload, generation date, publication date, run state and original receipt remain untouched. Exact retries return the saved receipt. An unpublished edition, metadata mismatch or delivery mismatch cannot gain a presentation receipt. No database schema migration or fabricated new news run is needed. confirm-publication still rejects a changed first-publication release.

Review, privacy and final delivery owners

Public pushes are gated on exact outgoing files/commits, full-redaction Gitleaks, separate path/network/personal-data review and inspection of media content/metadata. Runtime configuration and detailed scanner/authoring logs remain private. Scanning alone is not a complete privacy proof.

Asif explicitly authorized the merges. Independent standards and requirements reviews provide the technical review record; the authenticated author account cannot submit a formal self-approval under GitHub’s rules. The release PR and publish workflow own the final merge/deployment result, and the verified presentation receipt owns delivered-reader provenance.

Limits

The tour is a recording, not the live app; its separate reader action opens the interactive product. Stories and dates are a retained edition, not a newly collected news run. Safari, screen readers and forced-colour modes were not tested. Repository renaming changes the Pages project URL; maintained entry points use the new address. The old preview directory is temporary and may be replaced by the production publish.
