# News-only PostgreSQL MVP implementation plan

Goal: complete the four-source news workflow through a private, inspectable HTML edition with retained data and a resumable database-backed run record. Execute in this session; Asif explicitly authorized planning, implementation and verification without intermediate approval gates.

Architecture: one Python workflow; PostgreSQL database `news`; typed relational identity, membership and decision columns plus JSONB for versioned source snapshots and model audit. A run fixes its input, editorial profile, prompt versions and stage outputs. Resume reuses completed stages; unfinished work can repeat safely. Render an edition snapshot into static HTML; no automatic deployment or email.

Constraints: existing `feat/news-source-filtering` branch; four approved feeds; direct local LLM; private infrastructure/settings/data remain ignored; no changes to other databases; no merge or production deployment. Plans and operational reports stay outside the legacy published `docs/` directory. Preserve existing public behavior pending review. PostgreSQL via psycopg uses parameterized SQL and short transactions, not an ORM or orchestration framework.

## Files and contracts

- `src/news/migrations/001_news.sql`: versioned schema for sources, articles, observations, runs, stages, events/members, profile decisions, evidence, model calls, editions and size samples.
- `src/news/store.py`: `NewsStore.from_env()`, `migrate()`, run creation/load/lock, transactional stage completion, article upserts/observations, event/decision/evidence/edition persistence, history and storage stats. Database name must be `news`.
- `src/news/workflow.py`: explicit ordered `run_workflow(store, model, ..., run_id=None)`; stages collect, clean, group, qualify, retrieve, select, synthesize, render. Stores inputs and outputs, uses one run-level advisory lock, freezes run configuration and saves failures. No publishing side effects.
- `src/news/editorial.py` and `src/news/profile.json`: versioned starting editorial profile; complete broad qualification tags/reasons; final evidence-based selection with explicit rejection categories. Small batches bound qualification output; final selection remains global.
- `src/news/llm.py`: grouping/qualification/selection prompts, bounded JSON calls, private database audit hook, prompt hashes. Existing synthesis passage validation retained.
- `src/news/pipeline.py`: reuse collection and extraction; extract standalone synthesis without changing old local build behavior. Thin text/input limits remain explicit.
- `src/news/render.py`: escaped static news HTML plus private editorial review HTML, safe source links, source counts, stage decisions, exact prompts/profile, evidence basis and timestamp. Raw evidence/prompt traces stay private; reader HTML has intended story fields only.
- `src/news/__main__.py`: run, resume, migrate and stats CLI with ignored env configuration and sanitized errors.
- `tests/test_news_mvp.py`, `tests/test_news_database.py`, `tests/fixtures/news_grouping.json`, `src/news/evaluate.py`: deterministic and opt-in real database/model checks; no private fixtures.
- `src/news/README.md`, `.env.example`, `requirements-news.txt`, `dispatch_report.html`: commands, schema/query examples, review pointers, actual execution evidence, limits and accepted debt.

## Acceptance and scope limits

One command produces today's local reader HTML and a private review page with retained queryable evidence. Failures preserve observations and completed stages. Each source, article, event and decision can be traced to run/profile/prompt versions. A failed run cannot replace the public edition. Database growth is measurable; retention deletion is deferred, not silently enabled. Source expansion, multi-profile UI, autonomous agents, queues and production scheduling are deferred. Grouping from metadata can miss body-only distinctions; valid source passages do not prove semantic entailment. Editorial choices remain reviewable judgments.
